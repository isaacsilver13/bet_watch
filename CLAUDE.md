# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Standalone NFL/NBA odds comparison app: FastAPI backend with a canonical event/odds contract, a provider protocol (fixture / stub / The Odds API), optional PostgreSQL persistence for refresh runs and immutable offer observations, and a React/Vite frontend. The API surface is intentionally read-only — there is no automated bet placement or sportsbook account integration.

## Commands

Backend (Python >=3.9, package sources under `backend/`, installed via `pyproject.toml`):
```
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
docker compose up -d postgres
alembic upgrade head                                   # apply migrations (reversible: alembic downgrade base)
uvicorn app.main:app --app-dir backend --reload --port 8000
pytest                                                  # full suite (testpaths = backend/tests)
pytest backend/tests/test_api.py::test_name             # single test
ruff check .                                            # lint
```
To develop without spending provider credits: `$env:ODDS_PROVIDER = "fixture"` before starting uvicorn (deterministic sample odds, no live calls). `PROVIDER_MODE=fixture` is the default when unset. To hit real NFL/NBA lines, set `THE_ODDS_API_KEY`, `PROVIDER_MODE=live`, `ODDS_PROVIDER=the_odds_api` (never commit the key). `PERSISTENCE_ENABLED=false` runs without a database.

Frontend (from `frontend/`): `npm install`, `npm run dev` (Vite dev server proxies `/api` to `127.0.0.1:8000`), `npm run build`, `npm run lint` (this project's "lint" is `tsc -b --pretty false`, not eslint).

## Architecture

- `backend/app/providers/` holds the provider protocol (`base.py`), the credential-free `fixture.py` and `stub.py` implementations, and `the_odds_api/` (client + adapter) for the live integration. `cache.py` implements single-flight locking, stale last-known-good fallback, retry/backoff, and quota-aware throttling — when a live provider's remaining quota drops to/below `PROVIDER_MIN_QUOTA_REMAINING` (default 5), the cache suppresses further refresh and serves the last good snapshot instead of calling out again.
- `backend/app/domain/` defines the canonical event/odds contract: event IDs normalize team aliases and five-minute start-time buckets, while provider-specific offer IDs stay attached to each individual observation — the two ID schemes are deliberately not conflated.
- `backend/app/storage/` + `backend/migrations/` (Alembic) persist refresh runs, events, provider mappings, and immutable offer observations; failed refreshes are recorded with a typed error rather than stored as empty successes, and rows older than `OBSERVATION_RETENTION_DAYS` are pruned after each refresh.
- `backend/app/providers/kalshi/` is a read-only prediction-market adapter (public Kalshi endpoint, no key). Its contracts use a separate `PredictionContract` model and `/prediction-markets` route on purpose -- do not merge them into `Offer`/`/odds`. `KALSHI_ENABLED` defaults off and `KALSHI_BASE_URL` defaults to the official public Trade API host.
- `backend/app/api/routes.py` exposes only: `GET /api/v1/health`, `/status`, `/odds`, `/odds?...&force_refresh=true`, `/history?event_id=...&market_type=...`, `/prediction-markets?sport=...`. In live mode a plain `GET /odds` never calls the provider: it serves `OddsRepository.latest_comparisons` (written by `odds_snapshot` or a manual refresh) minus games that started over 4 hours ago, or the in-memory board when persistence is off; fixture mode still fetches its free sample board. `force_refresh` / `include_props` and `/status` `capabilities.public_expensive_refresh` all use `routes._may_spend` (admin token, or loopback with no forwarding header when no `ADMIN_REFRESH_SECRET` is set), so the board's Refresh buttons show only on the owner's machine. A per-event refresh action re-fetches only the selected market for that event and merges it into the existing board without touching other events/markets. `backend/app/api/slate.py` adds `GET /api/v1/slate?sport=nfl&season=&season_type=&week=` (week games, reference lines with ESPN preferred over nflverse, movement since open; 503 when persistence is off).
- NFL week board (`api/board.py`, `GET /api/v1/board?sport=nfl&season=&season_type=&week=&books=`): one read-only call returning the slate plus every game's newest pregame snapshot per book, the consensus, same-line best prices (`analytics/market.best_prices`, now with `coverage` counts shared with `/games/{id}/lines`), book-consensus movement, and batched starting-QB / short-week flags. `books` is a comma list of venue keys that scopes consensus and best; `snapshot_books` still lists every book. It never touches the provider runtime, so opening the page never spends credits. `lines_repository.side_offers_for_games` is the batch loader; `slate.week_slate` is shared with `/slate`. Frontend: `SlatePage` (URL-backed `market`, `team`, `books`, `game`, `panel`), `NflBoard`, `BookComparison`, `ResearchBrief`, `AppHeader`; the NBA keeps its own price table.
- `backend/app/analytics/` holds pure functions (no I/O, every one takes a `before` cutoff): `records.py` (SU/ATS/O-U), `situational.py` (rest, bye, travel, primetime), `efficiency.py` (EPA ranks), `injuries.py` (starting-QB flag). `backend/app/storage/context_repository.py` writes team stats, append-only injury snapshots (newest snapshot at or before kickoff wins) and one weather row per game; `backend/app/jobs/context.py` runs them (`team_stats`, `team_stats_history`, `injuries`, `weather`).
- `backend/app/api/matchup.py` adds `GET /api/v1/games/{id}` (a `SlateGame`) and `/games/{id}/context?last_n=` (records, efficiency, situation, injuries, head-to-head, `data_as_of`). ATS/O-U use the closing line, ESPN first then nflverse.
- `backend/app/ingest/` holds pure parsers (ESPN scoreboard/pickcenter, nflverse `games.csv`, the committed NFL team seed) that produce source-neutral `GameRecord`/`LineRecord` (`records.py`). `spread_home` is the home line everywhere; negative = home favored. Before kickoff, ESPN's "close" is stored as `current`.
- `backend/app/storage/games_repository.py` upserts games via `team_aliases` (no name hashing), never overwrites an `open` line, lets only ESPN downgrade status, and links odds `events` to `games`.
- Prices and bets (phase 1c): `backend/app/jobs/odds.py` (`odds_snapshot`, the only paid job: Tue/Thu/Sat/Sun 10am CT plus one slot 30 min before each kickoff time; the response is saved to `data/raw/` BEFORE parsing and the slot is `raw_saved` until it is stored, so a crash re-parses the file and never pays twice; `partial` retries once after a gap; the quota floor makes it `skipped_quota`; it does nothing unless `PROVIDER_MODE=live` with a key), `backend/app/ingest/odds_snapshot.py` + `odds_raw.py`, `analytics/{pricing,market,coverage,clv,fees,grading,bet_stats}.py` (pure: no-vig math, consensus, best price, CLV, effective-dated Illinois fee rules, grading), `storage/{lines,bets}_repository.py`, `api/lines.py` (`GET /games/{id}/lines`, which stops at kickoff once a game has started because the feed also returns in-game prices, and `POST /games/{id}/refresh` with a 10 minute cooldown, gated by `routes._may_spend`), `api/bets.py` (`/bets`, `/bets/summary`) and `api/ops.py` (`/ops/health`). `jobs/bets.py` (`grade_bets`, hourly) settles final games and copies the close onto started bets: the Odds API snapshot within 60 minutes before kickoff, else ESPN's close. `bets.line` is the bet side's own number (home -2.5, away +2.5, over 44.5); `close_price` is the no-vig fair price; `payout` is total returned, so profit = payout - stake - fee.
- `link_events` lets a newer odds event take over a game when the feed re-times it (flex), and `related_event_ids` gathers every event for a game so history spans both. Fee rules live in `analytics/fees.py`: add a new dated rule, never edit an old one (bets keep the fee they were charged).
- NBA (phase 2) reuses the NFL pipeline per sport. Teams: `ingest/data/nba_teams.csv` (ESPN abbreviations GS, NO, NY, SA, UTAH and WSH are aliases of GSW, NOP, NYK, SAS, UTA and WAS; the Clippers play in the Intuit Dome). Schedule: `ingest/espn.py` `fetch_scoreboard_day` (ESPN's day is the US Eastern date; a date-range query returns 400, so history loops per day), `jobs/nba.py` (`nba_scoreboard`, `nba_history`, `nba_team_stats`, plus `EspnClosesJob`/`LinkEventsJob`/`InjuriesJob` built with a sport and a name). Games have `week = NULL`; `Game.season` is the year the season ends (ESPN's convention, 2027 for 2026-27). Stats: `ingest/nba_stats.py` reads stats.nba.com `teamgamelogs` (Advanced and Four Factors) with plain httpx and browser headers, no nba_api; `ContextRepository.save_game_log_stats` matches by season, Eastern date and team pair. Analytics: `analytics/ratings.py` (possession-weighted), `analytics/schedule_spots.py`. `GET /games/{id}/context` branches on `game.sport`; `GET /slate/days?sport=nba&date=` is the day slate. Injury snapshots are per sport (`ContextRepository.injury_snapshot`), and `record_snapshot` and `latest_snapshot_at` are per sport because two sports can be snapshotted in the same second. `OddsSnapshotJob(sport, name)`: NBA = 10am Central daily plus the first and last tip of each Central date (`nba_pre_tip_slots`), sharing the one credit pool.
- Official injuries and stars (phase 3): `ingest/nba_injury_report.py` reads the league's PDF by word position (`pypdf` `visitor_text`; its layout mode scrambles the page), `ingest/nflverse_injuries.py` reads the nflverse CSV; both produce `NamedInjury` and `ContextRepository.save_official_injuries` stores them under `injuries.source` `nba_official` / `nflverse`. `merged_injuries` (behind `injury_snapshot`) takes each source's newest snapshot and merges by `name_key`: official over ESPN. `player_season_stats` (migration 0005, job `nba_player_stats`) feeds `analytics/stars.py` (top 3 by minutes per game, at least 5 games; last season decides until a team has played 10). `storage/badges.py` builds `SlateGame.star` and `SlateGame.bets`; each team in `ContextResponse` carries `star_flag` (null for the NFL). Jobs: `nfl_injuries_official` (daily + Wed-Fri 18:00), `nba_injuries_official` (hourly 10:00-22:00), `nba_player_stats` (daily).
- Model picks (daily report 3b): `jobs/model_picks.py` (`model_picks`, free) reads the nba repo's predictions JSON (`NBA_PREDICTIONS_DIR`), joins on Eastern date + tricode (= `teams.abbr`), and prices every book with `analytics/picks.py` (fee-adjusted EV at `MODEL_PICK_STAKE`, fractional Kelly; moneyline EV > 3% `targeted`, spreads `watchlist`). Offers carry the feed's book title, so fees are looked up via `domain/venues.venue_for_book`. Its slot (10:15 CT) is planned only once today's `odds_snapshot_nba` open slot is terminal. Picks (`model_picks`, migration 0006) are stored once per slate; the report POST to AIsaac `/internal/nba-report` failing leaves the slot `pending` so the next tick re-sends the stored picks. The push target comes from env or `~/.claude/aisaac_push.json` (`config._PUSH_CONFIG_PATH`, redirected in `conftest.py`). `settlement.grade_model_picks` (run by `grade_bets`) fills `result` and the close; `clv` is ratio CLV. `GET /api/v1/model-picks` feeds the Bets page.
- `backend/app/jobs/` is the scheduler: `slots.py` (America/Chicago windows), `runner.py` (`run_due`: one state per `job_slots` row, attempts logged to `provider_refresh_runs`, past windows marked `missed` once, terminal slots never re-run), `nfl.py` (the jobs) and `__main__.py` (`python -m app.jobs run-due | <job>`). In production cron-job.org fires `run-due` every 15 min (07:00–23:45 CT) through the Fly app's `POST /internal/run-due` (`app/api/internal.py`, `INTERNAL_JOBS_SECRET`); never run `run-due` on the PC as well, since the in-process lock only covers the one Fly machine. Scheduled jobs are the only automatic spend; opening a page never refreshes.
- No code under `backend/app` currently references player-prop markets — if a task involves prop odds, treat that as unimplemented rather than assuming existing plumbing to extend.
- The UI is local; the Fly app `bet-watch` is a **jobs-only** service (owner's decision, 2026-10-22, so the NBA report doesn't depend on the PC being awake). Both use the same Neon Postgres (`DATABASE_URL`). CI deploys on pushes to master. On Fly the private-data boundary (`main.py`) still answers 403 to everything except public health GETs and `POST /internal/*`, which checks `INTERNAL_JOBS_SECRET`: `/internal/run-due` (cron-job.org) and `/internal/nba-predictions` (the nba repo's daily Actions workflow, written to `NBA_PREDICTIONS_DIR` on the `/data` volume). Internal responses carry slot-state and game counts only, never bets or stakes. Don't expose the journal or UI publicly.
